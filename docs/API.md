# Student API reference

Start the application using the [README](../README.md). The default base URL is
`http://127.0.0.1:8000`. Requests and responses use JSON, except for successful
deletion, which has no response body. Use dummy student information.

Interactive documentation: [/docs](http://127.0.0.1:8000/docs).
Alternative reference: [/redoc](http://127.0.0.1:8000/redoc).
Machine-readable contract: [/openapi.json](http://127.0.0.1:8000/openapi.json).

## Student fields

| Field | Input rule | Returned value |
| --- | --- | --- |
| `name` | Required on create; trimmed, 1-100 characters | String |
| `email` | Required on create; valid email syntax, unique after normalization | String |
| `age` | Required on create; JSON integer from 1 to 9223372036854775807 | Integer |
| `course` | Required on create; trimmed, 1-100 characters | String |
| `id` | Generated by SQLite; cannot be supplied in input | Positive integer |
| `created_at` | Generated by SQLite; cannot be supplied in input | ISO datetime string |

All fields are non-null. Strings and booleans are rejected for age. Unknown
input fields are rejected. The age upper bound reflects SQLite storage capacity;
the project does not impose a separate human-age policy. Email validation checks
syntax, not mailbox ownership or deliverability. Email domains are normalized;
uniqueness otherwise follows SQLite's case-sensitive comparison.

Creation timestamps represent UTC but serialize without an explicit timezone
suffix, for example `2026-10-22T12:00:00`. Updates preserve the creation time.
IDs are not guaranteed to be consecutive or permanently reserved after deletion.
Always use the ID returned by creation.

## Welcome

`GET /` returns **200**:

```json
{"message":"Student CRUD API is running"}
```

## Create

`POST /students` with `Content-Type: application/json`:

```json
{"name":"Demo Student","email":"demo@example.com","age":20,"course":"Computer Science"}
```

Returns **201** with the stored student. Illustrative generated values:

```json
{
  "id": 1,
  "name": "Demo Student",
  "email": "demo@example.com",
  "age": 20,
  "course": "Computer Science",
  "created_at": "2026-10-22T12:00:00"
}
```

Duplicate email: **409**. Invalid or missing input: **422**.

## List and filter

`GET /students` returns **200** with a plain array of student objects, ordered
by ascending ID. There is no total-count wrapper. No matches return `[]`.

| Optional query parameter | Meaning | Default and bounds |
| --- | --- | --- |
| `name` | Literal substring of the name | Omitted; 1-100 characters if supplied |
| `course` | Exact course match | Omitted; 1-100 characters if supplied |
| `limit` | Maximum results on this page | 100; integer from 1 to 100 |
| `offset` | Matching records to skip | 0; integer from 0 to 9223372036854775807 |

Both text filters ignore ASCII case. Non-ASCII case folding is not guaranteed.
Filters combine with AND and are applied before pagination. Query whitespace is
not trimmed. `%` and `_` are literal characters, not wildcard operators.

```http
GET /students?name=demo&course=Computer%20Science&limit=10&offset=0
```

Use `offset=10` for the next page with `limit=10`. Concurrent changes can affect
page contents. Invalid query values return **422**.

## View

`GET /students/{student_id}` returns **200** with one student object, or **404**
if it does not exist. IDs on all individual-student routes must be integers
from 1 to 9223372036854775807; invalid IDs return **422**.

## Partial update

`PATCH /students/{student_id}` with `Content-Type: application/json`:

```json
{"course":"Mathematics"}
```

Returns **200** with the complete updated student. Omitted fields remain
unchanged. Supply at least one of `name`, `email`, `age`, or `course`; `{}` and
explicit `null` values return **422**. Although optional update fields may be
shown as nullable in the generated schema, the request validator rejects nulls.
Supplying all four fields is also supported. `PUT` is not implemented.

Missing student: **404**. Another student's email: **409**. Reusing the same
student's existing email is allowed. Failed updates leave the record unchanged.

## Delete

`DELETE /students/{student_id}` returns **204** with an empty response body.
Do not try to parse it as JSON. A subsequent GET or DELETE for that ID returns
**404**, unless another record has since reused the ID.

## Error responses

| Status | Meaning | Typical correction |
| --- | --- | --- |
| 404 | Student does not exist | Use a current ID returned by create/list |
| 409 | Email already registered | Supply another email or update the existing student |
| 422 | Invalid body, field, path, or query | Read `detail` and correct the input |

Missing student:

```json
{"detail":"Student not found"}
```

Duplicate email:

```json
{"detail":"Email is already registered"}
```

For `{"age":0}` in a PATCH request, a representative validation response is:

```json
{
  "detail": [
    {
      "type": "greater_than",
      "loc": ["body", "age"],
      "msg": "Input should be greater than 0",
      "input": 0,
      "ctx": {"gt": 0}
    }
  ]
}
```

Validation text and additional keys can vary with installed dependency versions.
Use `loc` to find the failing input. PowerShell's `Invoke-RestMethod` throws on
error status codes; use `/docs` or the demo below to inspect expected errors.

## Runnable walkthrough

In one PowerShell window, start the server as described in the README. In a
second window at the repository root:

```powershell
.\.venv\Scripts\python.exe examples/demo.py
```

The demo uses Python's standard library. It checks the welcome response, creates
a unique dummy student, views and filters records, demonstrates 409 and 422
responses, updates the course, deletes its student, and demonstrates 404. Each
step prints its status and JSON response. It cleans up its created record in a
`finally` block; cleanup requires the server to remain reachable. It does not
delete other records. The list response may include existing matching students.

For a different local port:

```powershell
.\.venv\Scripts\python.exe examples/demo.py --base-url http://127.0.0.1:8001
```

## Storage and project limits

The database is `data/students.db`, resolved relative to the project files and
excluded from Git. Startup creates missing storage. Committed records persist
across restarts. Each operation uses a short-lived connection and transaction.
Tests use temporary databases; the demo uses the running server's database.

This is a local learning API without authentication, a frontend, or deployment
configuration. The root welcome response confirms that the app responds; it is
not a database health check.
